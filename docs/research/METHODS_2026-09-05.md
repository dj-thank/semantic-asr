# Research methods and falsifiable proposals — 2026-09-05

Status: planning notes linked to #23 and #21, not measured improvements. Sources
below were checked on 2026-09-05. Papers support the described method, not the
performance of this repository. Online documentation is mutable: execution must
pin the library/model revision and preserve the actual configuration.

## 1. Exact CTC and conditional alignment — #33, #34, #35

Primary API: https://docs.pytorch.org/docs/stable/generated/torch.nn.CTCLoss.html

CTC sums compatible frame-label paths. Repeated labels require appropriate blank
separation; zero_infinity can hide impossible training examples by zeroing their
loss/gradient. An alignment conditioned on a transcript does not prove it was said.

Proposal: retain exact zero support, validate length/repetition and compare any
optimized kernel against enumeration and the existing scalar implementation.
Control: same posterior and target, including repeats, empty/unsupported targets
and extreme scores. Reject an optimization if likelihood or feasible-path behavior
changes. Preserve unsupported-candidate reasons rather than failing an entire file.

## 2. Self-supervised speech encoders plus supervised heads — #35, #36

HuBERT: https://arxiv.org/abs/2106.07447 (2021).
wav2vec 2.0: https://arxiv.org/abs/2006.11477 (2020).

These provide ways to learn speech representations before task-specific labeled
adaptation. Their published results are not evidence of our Japanese phone accuracy.
Proposal: new phone/mora heads on a frozen licensed encoder, then controlled partial
fine-tuning. Controls: phone-only, mora-only, joint, frozen versus partial encoder.
Record actual tensor updates and reloadable checkpoints. Reject deployment if
paired errors, false corrections or compute budgets fail the fixed gate. Do not
invent boundary/accent/F0 supervision where reliable labels are absent.

## 3. Pronunciation uncertainty is not independent evidence — #33

Current model card:
https://huggingface.co/prj-beatrice/japanese-hubert-base-phoneme-ctc-v4
Repository evidence: ../PHONETIC_ERROR_DRIVEN_2026-09-05.md

Use the model card and the retained errors to inspect weak-label assumptions.
A text-derived reading can be wrong even for the correct written word. Proposal:
multiple pronunciation variants with normalized priors and explicit G2P provenance.
Compare against a single reading on the same development clips, with a reviewed
phonetic subset separate from G2P proxies. Duplicate variants must not add evidence;
phone-derived morae must not be counted as another independent witness. Reject the
variant system if it only improves by exploiting more alternatives or harms exact
utterances. This proposal does not resolve all Japanese allophony or dialects.

## 4. Actual LLM adaptation with LoRA — #35, #37

Paper: https://arxiv.org/abs/2106.09685 (2021).
API: https://huggingface.co/docs/peft/main/en/package_reference/lora

LoRA trains low-rank parameter updates while retaining a frozen base. Prompting or
fitting a fusion coefficient is not LoRA training. Proposal: a candidate ranking or
abstention objective, with audio support kept as a separate constrained signal.
Controls: frozen base, small linear ranker, LoRA, and no-audio ablation. Shuffle
candidate order to test rank/ID shortcuts. Check updated adapter and unchanged base
tensors, reload into a new process, and measure false corrections as well as CER.
Reject free-form observation rewriting and any apparent gain from reference leakage.
The plan is adaptation of an existing base, not foundation-model pretraining.

## 5. Sample-based MBR for autoregressive ASR — #39

https://arxiv.org/abs/2510.19471v2
Submitted 2025-10-22; revised 2026-05-13.

The paper evaluates sample-based MBR with Whisper-family models on English and
Japanese. Proposal: compare bounded sampled diversity with beam candidates under
the same runtime budget. Keep different decode score domains distinct. Report
candidate oracle, achieved selection error and latency separately. Reject adoption
when extra candidates improve only the oracle or exceed the budget. This is an
offline research direction, not an already verified repository improvement.

## 6. NAR-MBR is a different architectural branch — #39, deferred

https://arxiv.org/abs/2606.17537v1 (submitted 2026-06-16).

This method exploits non-autoregressive outputs to obtain multiple samples with
one forward computation. That premise is not a drop-in property of autoregressive
Whisper. Record it as an alternative architecture, not a reason to replace the
current runtime before baselines and profiling exist. Any future trial must use
an actual compatible NAR model and equal quality/cost comparisons. Defer if the
necessary model, rights or compute are unavailable.

## 7. Locked data and independent evaluation — #26, #29, #30

FLEURS: https://huggingface.co/datasets/google/fleurs
ReazonSpeech usage: https://research.reazon.jp/projects/ReazonSpeech/howto.html

FLEURS provides documented splits and license metadata; derived speaker/session
splits still need verification. Public access does not grant every redistribution
operation. Use train/dev/calibration/test/exposed roles and operation-specific
rights. Existing inspected samples become regression evidence, not a fresh test.

Proposed evaluation: strict and lenient CER, verified phone/mora metrics or clearly
labeled G2P proxies, semantic-critical slices, false correction and risk/coverage.
Use paired group-aware uncertainty and preregister metrics/budgets before test
inspection. Falsification includes leakage, new harms, a confidence interval
compatible with no gain, and reliance only on changed spelling normalization.

## 8. Real document context needs real documents — #38

This is a repository-specific experimental proposal, motivated by the limitations
in the two-cycle report, not a result borrowed from unrelated short-clip benchmarks.
Use permitted continuous recordings with frozen first-pass context. Compare none,
left-only, bidirectional offline, shuffled context and distracting versus relevant
catalogs. Separate online from future-context offline results. Preserve fillers,
repairs and uncertainty; never use reference transcripts as contextual evidence.
Reject the claimed benefit if it disappears under controlled ordering or increases
unsupported edits. Synthetic concatenations are boundary tests, not meeting-quality
benchmarks.

## 9. Reproducible weights and knowledge records — #28, #35, #40

PyTorch reproducibility: https://docs.pytorch.org/docs/stable/notes/randomness.html
Tensor format: https://huggingface.co/docs/safetensors/index
Discussions: https://docs.github.com/discussions/quickstart
Issue forms: https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms

Pin execution environments; a seed alone is not a cross-version/hardware identity.
Separate publicly shareable tensor weights from trusted local optimizer/resume
states. Tensor-safe loading does not validate model rights or scientific claims.
Preserve full trial ledgers, checkpoints and negative findings with hashes and
source revisions. Use Issues for work and versioned ADRs for final decisions;
Discussions can hold debate, but no discussion category was created by these notes.

Each experiment must instantiate the preregistration and result template at
[development/TEMPLATES.md](../development/TEMPLATES.md). No result in this document
licenses SOTA, zero-error, newly trained, GPU-tested or publication-ready claims.
