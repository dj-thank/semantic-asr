# Dataset lineage, split visibility, and operation-specific rights

This document defines the data contract used by the Semantic ASR v0.2 research stack. It is a
fail-closed contract for reproducibility and publication safety; it is not evidence that any
particular corpus is licensed for a particular use.

## Five canonical roles

Every utterance has exactly one role:

| Role | Reference visibility | Intended use |
| --- | --- | --- |
| `train` | model-visible | fit model or ranker parameters |
| `dev` | model-visible | development and checkpoint selection |
| `calibration` | calibration-only | fit confidence, risk, and routing thresholds |
| `test` | evaluation-only | untouched publication evaluation |
| `regression-exposed` | evaluation-only | already viewed or published regression examples |

The spelling is exact. Whitespace, case aliases, `development`, and underscore variants are
invalid. `test` and `regression-exposed` references are rejected by model-context and training
loaders at both the public type boundary and runtime. A missing split is not treated as `train`.

`regression-exposed` is deliberately separate from `test`. An example remains useful for
regression testing after it has been inspected, but it can no longer support a fresh-test claim.

## Manifest identity

`DatasetManifest` binds all of the following into its SHA-256 digest:

- dataset name and exact revision;
- rights registry digest;
- split policy name and integer seed;
- cumulative sample, audio, and normalized-reference exclusions;
- every record and its lineage fields.

The v2 JSON schema requires raw-file and normalized-PCM SHA-256 values, source dataset revision,
rights asset ID, explicit nullable speaker/session/source IDs, derivation and reference lineage,
near-duplicate group, parent sample IDs, and metadata. The canonical validator rejects unknown
fields, snake-case aliases, type coercion, and missing required nullable keys. Runtime objects
continue to read legacy records for audit, but lineage validation fails when normalized PCM or the
source revision is missing. `integrity_report()` exposes unknown speakers and rights identities
instead of silently claiming speaker-disjointness or permission completeness.

The reference digest is computed after Unicode NFKC normalization and whitespace removal. It is a
coarse exact-normalization guard, not a semantic near-duplicate detector. Alternate readings,
segment variants, augmentations, and other known relations must share an explicit
`nearDuplicateId`, `referenceLineageId`, `derivationGroupId`, source recording, session, or parent
lineage.

## Leakage and lineage gates

`DatasetManifest.leakage_findings()` checks cross-role identity for:

- source-file and normalized-PCM hashes;
- speaker and session IDs;
- source recording IDs;
- normalized reference digests;
- reference-lineage, derivation-group, and near-duplicate IDs;
- parent/derived sample relations.

It also rejects any `test` row matching cumulative exclusions by sample ID, audio hash, or
normalized-reference hash. `integrity_report()` separately records missing parents, cycles,
record-level dataset revision mismatches, unknown speakers, and unknown rights assets.

Unknown speakers are not assigned a fake common ID. The report sets
`speakerDisjointGuaranteed=false`; callers may use `require_known_speakers=True` when the study
requires a speaker-disjoint claim.

## Operation-specific rights

The existing rights registry remains authoritative. Version 2 records `allow`, `deny`, or `review`
for each operation:

- `train`
- `evaluate`
- `derive_features`
- `publish_text`
- `publish_features`
- `publish_weights`
- `redistribute_audio`

The legacy `redistribute_raw` and privacy-specific `export_speaker_id` operations remain available
during migration. A v1 `redistributeRaw` decision migrates only to the equivalent raw-audio
operation; missing new permissions migrate to `review`, never `allow`.

A record also stores the exact asset revision, license source, review/acquisition dates,
attribution, optional license-text digest, and optional consent record. Registry digests are
canonical and independent of asset order. A v2 file may carry `registryDigest`; the loader rejects
it when it does not match the canonical asset contents. It also rejects unknown v2 fields and type
coercion while retaining explicit v1 migration behavior. `DatasetManifest.require_operation_rights()`
verifies the pinned registry digest, requires every selected sample to have a known asset, and stops
on both `deny` and `review` before processing.

## Local and public manifests

The local manifest may contain references, speaker pseudonyms, and local-only metadata. The public
redaction generated by `public_redacted_payload()` omits:

- reference text;
- speaker identifiers;
- arbitrary metadata, including local paths.

Sample, source/session, and lineage identifiers are replaced with SHA-256 digests. This redaction does not grant
publication permission: `publish_text`, `publish_features`, `redistribute_audio`, and any other
actual operation still require an explicit `allow` decision.

Validate a complete local manifest and emit the redacted public view with:

```bash
PYTHONPATH=src python scripts/validate_v02_manifest.py \
  examples/v02-experiment-manifest.json \
  --require-known-speakers \
  --require-known-rights \
  --public-redacted-output /outside/checkout/public-manifest.json
```

Use `--allow-reference-duplicates` only for a preregistered study whose exact duplicate handling is
reported separately. It does not disable source, audio, speaker, session, derivation, parent, or
cumulative-exclusion checks.

## Migration from the legacy three-role manifest

1. Pin the dataset revision and rights registry digest.
2. Keep already inspected/public examples in `regression-exposed`; do not relabel them as fresh
   `test`.
3. Split the former training material into `train` and `dev` by source/speaker/lineage group, not by
   row.
4. Populate normalized PCM hashes and explicit nullable identity fields.
5. Record cumulative exclusions for every sample/reference/audio item that has influenced system
   design.
6. Add operation-specific rights. Unreviewed operations remain `review`.
7. Run schema validation, lineage validation, redaction inspection, and the full test suite before
   consuming any reference-bearing artifact.
