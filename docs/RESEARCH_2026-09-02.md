# Research and measurement ledger — 2026-09-02

This ledger records the first executed real-audio run of Semantic ASR, the defects it exposed,
the fixes, and the 2025–2026 literature reviewed while deciding what to build next. Numbers
here are evidence only for the exact manifest, model, runtime and configuration named.

## 2. Defects found by running real audio

### 2.1 Unpadded Whisper window (root cause)

`FasterWhisperAdapter`, `PathPreservingFasterWhisperAdapter` and `FasterWhisperPathAdapter`
called `WhisperModel.encode()` on the raw log-mel features of the clip. `faster_whisper.transcribe`
always pads a segment to one 30 s window (`pad_or_trim`) before encoding. Whisper was trained
only on 30 s windows; an encoder run on 80 frames for a 0.8 s clip produces hallucinated,
looping decodes on every beam, so N-best diversity, MBR and oracle@K cannot recover.

Fix: `pad_features_to_window()` in `adapters.py`, applied by all three adapters.

### 2.2 No degenerate-decode protection on the direct generate path

`faster_whisper.transcribe` additionally applies a compression-ratio threshold (2.4), a
log-probability threshold (−1.0) and a temperature fallback. Calling `model.generate()`
directly skipped all three. Fix: `LoopGuardConfig` in `advanced_adapters.py`:

- duration-aware `max_length` (32 + 14 tokens/s, capped at 440 new tokens);
- per-path degeneracy evidence: zlib compression ratio, repeated 4-gram fraction, character
  budget (8 + 12 chars/s), average log-probability;
- staged fallback (beam → sampling at T = 0.2 … 1.0) where every stage keeps its own score
  domain and `decodeStage`, so sampled scores are never summed with beam scores;
- degenerate paths are dropped when a healthy path exists (never returns an empty pool);
- timestamp tokens are enabled in the prompt by default (`--without-timestamps` restores the
  v0.2 prompt).

### 2.3 Single-candidate utterances aborted ranker training

After path aggregation and loop-guard rejection many utterances keep one surface. The
ranker loaders now skip those rows and report the count.

### 2.4 Metric comparability

Published Japanese numbers (kotoba-whisper model cards, Neosophie 2026 benchmarks) strip
punctuation before CER and weight by corpus length. The benchmark now reports, next to the
strict utterance-mean CER, `corpus_cer` (length-weighted) and `lenient_corpus_cer`
(NFKC, whitespace/punctuation/symbol stripped). Strict CER remains the primary metric because
observed transcripts must not silently lose punctuation.

## 4. 600-clip run (ReazonSpeech test subset, locked test split n = 116)

Partition: train 365 / calibration 119 / test 116. 23 training utterances had a single
surviving surface and were skipped by the ranker loaders. Utterance-mean strict CER unless
noted; `lenient` = corpus-level, punctuation/symbol stripped.

A later isolation audit found two normalized-reference duplicates crossing train and
calibration, while the source exposes no speaker identity. The historical split therefore remains
**conditional legacy evidence**, not a promotion-quality speaker/duplicate-disjoint result. New
manifest generation uses stable audio digests and assigns identical normalized-reference digests
to one split; both runtime manifest and benchmark verification also recompute reference leakage.

| system (test split, n = 116) | strict CER | corpus CER | lenient CER | oracle@3 | oracle@12 |
|---|---|---|---|---|---|
| raw ASR top-1, no loop guard (padding only) | 0.2608 | 0.1522 | 0.1215 | 0.2007 | 0.1780 |
| raw ASR top-1, loop guard (default) | 0.2518 | 0.1486 | 0.1162 | 0.2080 | 0.1915 |
| + 8 sampled candidates (T = 1.0, top-k 10) | 0.2512 | 0.1482 | 0.1159 | 0.2067 | **0.1543** |
| Semantic MBR (default pool) | 0.2646 | 0.1525 | 0.1197 | - | - |
| Semantic MBR (+ 8 samples) | 0.2632 | 0.1538 | 0.1204 | - | - |

| fusion cascade + pairwise ranker + calibration | 0.2518 | 0.1486 | 0.1162 | - | - |

Ranker training and calibration on the real splits:

```text
listwise MWER   expected loss 0.188 -> 0.165, top-1 loss unchanged (0.163), oracle 0.102
pairwise        pairwise accuracy 0.60, logistic loss 0.061 -> 0.055
calibration     ECE 0.258 -> 0.036 (listwise), 0.294 -> 0.046 (pairwise), NLL 0.91 -> 0.48
```

### What the numbers say

1. **The padding fix is the whole story so far.** With padded windows the raw top-1 is at
   the level published for Whisper large-v3 on this test set (kotoba-whisper card: 14.9 CER
   with a different normalizer), so the pipeline now produces a credible baseline.
2. **The loop guard's effect on this split is within run-to-run noise.** Top-1 moved
   0.2608 -> 0.2518 strict, but oracle@12 moved 0.178 -> 0.192. Inspecting the ten utterances
   where the guarded pool lost its oracle-best hypothesis showed that none of those
   hypotheses had been flagged degenerate; they were simply never generated in the second
   run. A follow-up run that kept low-logprob-only paths (then reverted) landed at 0.2622
   top-1 with the identical oracle curve. With padded windows the beam search is at a
   near-tie regime where int8 CPU kernels under different thread counts flip hypotheses;
   the loop guard's measurable value is confined to all-degenerate clips (the 1.4 s dialect
   case in the pilot), and the thread count is now recorded in decode provenance
   (`ompNumThreads`). Any claim below about ±0.01 strict CER needs repeated runs.
3. **Sampled enrichment raises the ceiling** (oracle@12 0.192 -> 0.154) at no top-1 cost, which
   is the precondition for any reranker or MBR gain, matching the TMLR 2026 MBR finding.
4. **The v0.2 learned rerankers do nothing on real data.** In all 116 test utterances the
   calibrated ranker top candidate equals the ASR top candidate; cascade CER equals raw CER
   with a bootstrap interval of exactly zero. The dependency-free feature set is dominated by
   the acoustic rank/score it is trained alongside. Calibration works (ECE 0.04) but it is
   calibrating a ranker that carries no new information.
5. **Semantic MBR is slightly harmful** on this pool (+0.013 strict), consistent with the
   TMLR 2026 caveat that MBR needs a real sample-based posterior and a utility that is not the
   evaluation metric; the current posterior is a softmax over path scores of 3-6 surfaces.
6. **Critical-slice detection over-fires**: 98 of 116 references are tagged critical, so the
   slice is not yet informative.

Rank regret headroom is 0.06-0.10 strict CER. Closing it requires evidence the acoustic score
does not already contain: character/mora n-gram LM scores trained on rights-cleared text,
cross-model agreement with the Qwen3-ASR second ear, and the degeneracy/stage features now
exported per path.

## 4b. Qwen3-ASR-0.6B as a CPU second ear (probe, 20 pilot clips)

`scripts/probe_second_ear.py` with the transformers backend, float32, `device_map=cpu`:

```text
model load            108 s
real-time factor      median 0.83 (Ryzen 7 5700X, 6 threads, contended)
lenient CER (n=20)    Qwen3-ASR-0.6B 0.256  vs  large-v3-turbo int8 0.215
```

Qwen writes numerals as kanji (十五種類) where ReazonSpeech references use Arabic digits, so
its lenient CER is inflated by normalization rather than recognition; it produced no
repetition loop on any pilot clip, including the 1.4 s dialect clip where every Whisper stage

islands, all-degenerate pools) rather than an always-on pass. Twenty clips is a feasibility
probe, not a quality claim.

## 4c. Evidence enrichment experiments (test split n = 116, strict utterance-mean CER)

`semantic-asr enrich-candidates` attaches evidence that the Whisper decoder score does not
contain. Second ear: Qwen3-ASR-0.6B on CPU (float32, all 600 clips, median RTF 0.51).
Language model: character 5-gram on a 12 MB Japanese Wikipedia subset (CC BY-SA, derived
features only). "cascade" is the fusion cascade with the new streams; "listwise" is the
fusion cascade after listwise ranker training and held-out calibration on the same streams.

| condition | cascade | listwise | Δ vs raw (95 % group bootstrap) |
|---|---|---|---|
| raw (no enrichment) | 0.2518 | 0.2518 | – |
| E1 `cross_model` = agreement with Qwen3-ASR-0.6B | 0.2596 | 0.2582 | −0.008 [−0.019, −0.001] (worse) |
| E2 E1 + char 5-gram `lexical` | 0.2548 | 0.2546 | −0.003 [−0.014, +0.006] |
| E3 E2 + Qwen hypothesis added as candidate | 0.3036 | 0.3139 | −0.052 [−0.102, −0.012] (worse) |
| E4 char 5-gram `lexical` only | 0.2636 | 0.2530 | −0.001 [−0.004, +0.001] |

Oracle@12 is unchanged by E1/E2/E4 (0.1915) and moves to 0.1852 when the Qwen hypothesis is
added (E3): the second ear rarely holds the right answer when Whisper does not.

### Interpretation

- The 20-clip pilot gain from `cross_model` (0.300 → 0.134) did not survive the locked test
  split; it was sampling noise. Agreement with a *weaker* second ear (Qwen3-ASR-0.6B has a
  higher CER than large-v3-turbo on this data) pulls selection toward the second ear's own
  errors. A second ear is only useful as evidence when it is at least as strong as the first,
  or when restricted to all-degenerate pools where the first ear produced nothing usable.
- A written-text character LM carries no useful signal for broadcast speech through either
  the fusion prior or the trained ranker (learned weights stay on rank features).
- The remaining rank-regret headroom (strict 0.060, lenient 0.060, so it is real content and
  not punctuation) decomposes over the 58 utterances where a better candidate exists into
  19 punctuation-only differences and 39 content differences. The content differences are
  dominated by proper-noun/homophone confusions and by trailing speech that Whisper transcribed
  beyond the ReazonSpeech reference segment. The latter is a corpus segmentation artifact; a
  reranker that learns to prefer shorter candidates would be fitting the artifact, not speech.

### What this changes in the roadmap

1. Proper nouns are the only recoverable content class in this data. That points to
   contextual biasing (hotword retrieval, arXiv:2512.21828; RECOVER-style entity evidence)
   rather than generic rescoring.
2. Second-ear agreement should be gated: use it only for utterances whose Whisper pool is
   entirely degenerate, or with a second ear of at least equal strength (Qwen3-ASR-1.7B on
   GPU), measured before it is allowed into fusion.
3. Evaluation on ReazonSpeech must handle segment-boundary artifacts explicitly (e.g. score
   only the reference span, or use a corpus with aligned utterance boundaries) before any
   length-sensitive reranking is trusted.

## 4d. Bounded follow-up discovery

Four independent, aggregate-only probes tested the remaining low-cost directions. All
hyperparameters and gates were selected on train/calibration; the locked test was evaluated
once and individual transcripts were not exported.

| direction | calibration decision | locked-test result | decision |
|---|---|---|---|
| train-reference in-domain character LM | order 2, alpha 0.5, weight 1.5 | strict `0.25185 -> 0.26892`; baseline-minus-system 95% CI `[-0.05134, +0.01223]` | reject |
| Wikipedia 5-gram direct rerank | weight 0.15 | strict `0.25185 -> 0.25931`; 95% CI `[-0.01792, -0.00092]` | reject |
| Qwen uncertainty + surface-match gate | margin `<=0.01` or entropy `>=0.9995`, call cap 20% | called 25/116, changed 3; strict delta `-0.00056` CI `[-0.00502,+0.00241]` | reject |
| Qwen only for all-degenerate pools | fixed predicate | covered 1/116; strict delta `-0.00172`, lenient delta `0` | hold, insufficient evidence |

The boundary probe reproduced the baseline exactly (`0.251850` utterance mean, `0.148564`
strict corpus, `0.116230` lenient corpus). A best-contiguous alignment diagnostic attributes
97 edit characters across 21 rows to hypothesis prefix/suffix overrun: aligned corpus CER is
`0.116540`, with 96 prefix and 48 suffix characters. In the predeclared `length >= 1.25`
slice (8/116), strict corpus CER is `0.730570` versus diagnostic aligned `0.367876`.

This is evidence that reference-window mismatch materially affects the headline strict metric;
it is **not** a better recognition score. The typed diagnostic added to `evaluation.py` returns
only edit/length/overrun counts. Benchmark reports include fixed length-ratio slices, but neither
alignment nor slice membership is available to fusion, ranking, thresholds, or pass/fail gates.

Current primary-source review also narrows contextual biasing: published gains frequently use
oracle or test-derived entity lists. A valid next experiment needs an exogenous, frozen catalog,
a distractor-only/no-bias arm, calibration-only thresholds, and separate entity/non-entity false
positive reporting. Without such a catalog, contextual biasing remains deferred rather than
being simulated from locked references.

### GPU route check

The local AMD RX 7600 XT passed a DirectML matrix-multiplication probe in an isolated
`torch-directml 0.2.5` / PyTorch 2.4.1 environment. Pinned Qwen3-ASR-0.6B did not complete one
public-audio inference: the model hit independent DirectML failures in the variable-length audio
feature merge and text embedding path. After four bounded compatibility probes, the native
DirectML route was rejected. Qwen3-ASR-1.7B remains a supported-GPU experiment, not an executed
result; CUDA/ROCm/vLLM or an official converted artifact is required.

The first revision-bound 600-clip reproduction attempt also found an operational defect: the
old command retained every result in memory and wrote JSONL only after all clips completed. After
roughly 80 minutes it hit `mkl_malloc` while sharing memory with an independent LLM probe, leaving
no candidate rows. That run is `NOT_RUN_TO_COMPLETION`, not a benchmark. Generation now fsyncs a
verified row checkpoint per utterance, validates the input/config/model-revision prefix on resume,
and promotes the final output atomically only after every row succeeds.

### Cached causal-LM upper-bound probe

The existing `cached_lm.py` seam was tested before building a cache. A pinned
`LiquidAI/LFM2.5-350M@9e6c6ccf47cd318696e137d381a7ded8fe4df09f` teacher directly scored all
3,366 candidate occurrences (3,351 unique surfaces). Train+calibration selected rank
normalization, weight `0.25`, and acoustic-margin gate `0.1` without reading test references.

The selected configuration already failed the protected fit criteria: strict utterance mean moved
`0.301671 -> 0.301270`, but strict corpus CER worsened `0.170645 -> 0.170888` and lenient corpus
CER worsened `0.141680 -> 0.142366`. On the locked test it changed 4/116 selections, moved strict
utterance mean `0.251850 -> 0.251988` (selected-minus-baseline 95% bootstrap
`[-0.000345,+0.000761]`), and left strict/lenient corpus CER unchanged. Decision: **reject this
teacher/configuration and do not build a probability cache**. The probe used the instruction-tuned
350M checkpoint, not the base checkpoint, so it does not falsify every possible cached-LLM teacher;
it does close this cheap local route.

### Native Japanese verbatim-fidelity pilot

The public HTH casual-conversation preview was bound at dataset revision
`9fde6880623724b58f8b26e6ba9fb96f04e9c88f`: 69 human-checked native Japanese
utterances / 324.1 s, with metadata-to-WAV coverage 69/69, 16 tagged filler events, 4 repair
spans and 3 uncertain spans. The repository declares no clear preview license, so the audit and
all transcripts remain local under `LOCAL_RESEARCH_ONLY_REVIEW`.

Pinned large-v3-turbo decoded 67/69 utterances; two returned runtime failures. Exact CER excludes
the 3 uncertain references, leaving 64 scorable rows. Strict CER is `0.4359` utterance mean /
`0.2848` corpus; lenient CER is `0.3952` / `0.2057`. The small conversation slice is much harder
than monologue (`0.5596` vs `0.2342` strict corpus; 37 vs 27 scorable rows), but four speakers and
five minutes are not enough for a population claim.

Most importantly, none of the 16 explicitly tagged filler **surface variants** matched
(`recall=0`, `F1=0`) under the pilot's exact-variant event metric, while two unmatched filler-like
forms were observed. This establishes an exact-surface fidelity gap, not proof that every filler
family was omitted; family-aware event alignment is the required follow-up. Two of four repair spans
were surface-matched. The product-relevant gap is largely hidden by ReazonSpeech, whose locked test
contains only 6 detected filler events. Filler preservation must remain a separate verbatim metric;
a readable normalized output may remove fillers only after, and independently from,
observed-transcript evaluation.

## 6. Claim boundary

- The pilot table is 20 clips; it demonstrates the defect and the fix, not a corpus-level rate.
- The 600-clip run is a 600-clip subset of the public test set, is not speaker-disjoint, and its
  historical partition contains two train/calibration normalized-reference overlaps. It uses one
  model/runtime on one CPU; report JSON with bootstrap intervals lives outside the repository
  because it carries reference transcripts.
- Nothing in this ledger shows a learned-reranker, MBR, second-ear-agreement, or n-gram
  improvement on the locked test split; every one of those conditions was measured and
  found neutral or harmful here.
- Boundary-aligned CER is diagnostic-only and must not replace strict CER, select candidates,
  tune thresholds, or be described as recognition improvement.
- No claim is made against published large-v3 or Qwen3-ASR numbers until the same
  normalization, full test set and model revisions are used.
